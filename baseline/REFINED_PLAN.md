# Контролируемое улучшение ручных признаков

Новый код: `refined.py`, запуск: `run_refined.py`. Только ручные формулы,
обучается CatBoost. Ранее сохранённые модели и данные не перезаписываются.
Положительные объекты не добавляются в кандидаты. Holdout не читается.

## Признаки

- 9 `ref_source_*`: попадание в исходный генератор, co-view top-100,
  популярность за 3 дня top-40, возрастную популярность top-30; число источников;
  позиции в трёх дополнительных источниках и исходный co-view score.
  Позиция co-view считается после удаления просмотренного, до объединения.
  Ранги популярности считаются до удаления просмотренного, как в исходном коде.
  Нет ранга: 99999. Связи с одинаковой популярностью разрешаются по item_id.
- 7 `ref_interest_*`: среднее трёх самых сильных co-view связей (либо всех,
  если история короче трёх); доля максимальной связи в сумме; взвешенная
  сходством давность; среднее по последним семи дням и более старой истории,
  их разница; среднее по всем объектам последнего наблюдаемого дня.
  Отсутствующие связи считаются нулевыми, отсутствие взвешенной давности — 999.
  Используется прежний разреженный граф top-150: отсутствие ребра не доказывает
  отсутствие исходного совместного просмотра.
- 21 `ref_lift_*`: для семи полей метаданных средний и максимальный log-lift
  токенов кандидата и их персональная поддержка. Каждый исторический объект
  делит единицу массы между своими уникальными токенами.
  `lift(t) = (personal_mass(t) + 10*global_probability(t)) /
  ((personal_total_mass+10)*global_probability(t))`.
  Вероятности глобального профиля считаются по тому же правилу на прошлом всех
  пользователей. Перед логарифмом lift ограничен [0.01, 100]. Не наблюдавшийся
  глобально токен получает нейтральный log-lift 0; пустые метаданные — нули.

История профилей полная. У графа сохраняется прежний лимит 100 пар/пользователя.
Никаких достоверных сеансов или порядка внутри одного дня не предполагается.

## Эксперименты

Все варианты используют одни и те же сохранённые кандидаты, метки и query_id
из запуска `20261023T085724_746626Z`. При подготовке проверяется точное совпадение
всех прежних колонок. Новые признаки строятся только по прошлому своего cutoff.

1. `v2_gpu`: точные имена 155 признаков сохранённой v2, новое обучение на GPU.
2. `v3_gpu`: все прежние 213 признаков, новое обучение на том же GPU.
3. `clean`: 154 признака v2 без `manual_user_history_size`, дублирующего
   `user_count_all`. Остальные найденные дубли относятся к v3 и в clean не входят.
4. `sources`: clean + источники кандидатов.
5. `interest`: clean + локальное сходство с историей.
6. `lift`: clean + относительные предпочтения метаданных.
7. `combined`: clean + все три группы.

По умолчанию seed 42, 43, 44, остальные основные параметры одинаковы.
Выбор деревьев: прежняя end-to-end NDCG@10 каждые 25 деревьев и последняя итерация.
Ранняя остановка CatBoost по внутренней метрике сохранена для сопоставимости;
она может остановить обучение до максимума по отчётной метрике.
Изменения качества анализируются по группам и seed. Все эти оценки — разработка
на известной validation-неделе, не независимое доказательство обобщения.

## Запуск

Из корня проекта, только в `baseline/.venv`:

```bash
# Маленькая полная проверка: 30 запросов на срез, 3 дерева, все 7 вариантов.
baseline/.venv/bin/python -u -m baseline.run_refined --smoke

# Полное сравнение: 7 вариантов × 3 seed. GPU проверяется до подготовки.
baseline/.venv/bin/python -u -m baseline.run_refined --output baseline/artifacts/refined/full_v1
```

Если подготовка уже выполнена с `--prepare-only`, та же команда переиспользует
её. `--prepare-only` не требует GPU. Прерванные отдельные обучения стартуют
заново; завершённые варианты пропускаются при совпадении конфигурации.
При изменении исходников нужен новый каталог запуска.
При ошибке подготовки используйте новый каталог: частичный кэш не продолжается.

Вывод: `run.log`, `status.json`, `source/`, `prepared/`, `summary.csv`, `aggregate.csv`, `comparisons.json`,
по каталогу на вариант и seed с моделью, важностями, кривой обучения,
метриками и индивидуальными оценками. Подготовленные таблицы между экспериментами
переиспользуются через hard links; исходный запуск остаётся отдельной копией.

## Проверки и ограничения

Проверки формул находятся в `tests/test_refined.py`:

```bash
baseline/.venv/bin/python -m unittest discover -s baseline/tests
```

Уточнение прежнего анализа: при дневных датах и `date < cutoff` условия
`age <= 7` и `date >= cutoff-7 days` эквивалентны. Исправления окна не требуется.
Отношения когорт с prior другого окна остаются прежними для чистоты сравнения.
BM25 — возможный следующий отдельный эксперимент после оценки этих групп.

Источники идей, не гарантия прироста:
- DIN, KDD 2018: https://arxiv.org/abs/1706.06978 — интерес относительно кандидата;
  здесь проверяется ручное приближение, а не реализация нейронного attention.
- NVIDIA Best Practices: https://docs.nvidia.com/deeplearning/performance/recsys-best-practices/index.html
- BM25 item-to-item, исходный код: https://github.com/benfred/implicit/blob/main/implicit/nearest_neighbours.py

`comparisons.json` содержит парные интервалы по пользователям отдельно для
каждого seed относительно `v2_gpu` и `clean`. Интервалы условны на выбранных
моделях, не учитывают подбор деревьев/признаков и множественные сравнения.
`aggregate.csv` показывает среднее и стандартное отклонение по seed;
для smoke с одним seed стандартное отклонение не определено.
