# Ручной baseline на KION

Двухэтапный рекомендатель: сначала собирает кандидатов по популярности,
предпочитаемым жанрам и совместным просмотрам, затем ранжирует их CatBoost.
Все признаки заданы вручную; обучаемых embeddings в этом решении нет.

## Результаты

На validation 9–16 августа 2021, 3328 тёплых пользователей:

| Вариант | NDCG@10 | Recall@10 | MAP@10 |
|---|---:|---:|---:|
| Популярность | 0.12330 | 0.18897 | 0.08363 |
| Исходный v1 | 0.14197 | 0.21253 | 0.09810 |
| Strong/expanded, CPU, 155 признаков | **0.16041** | 0.23361 | **0.11351** |
| Combined, GPU, seed 44, 191 признак | 0.16036 | **0.23466** | 0.11336 |

В Docker используется последний GPU-рецепт. Это лучший отдельный GPU-запуск
сравнения уточнённых признаков; исторический CPU strong чуть лучше по NDCG.
Среднее combined по трём seed: 0.159641 ± 0.000697 NDCG@10, не ансамбль.

Отдельная проверка strong на 3456 отложенных пользователях недели 16–23 августа:
NDCG@10 0.15272, Recall@10 0.22930, MAP@10 0.10455. Это другая группа
пользователей в известной неделе, а не новый независимый временной тест.

## Как это работает

Для пары пользователь–фильм считаются активность, давность, популярность в
окнах, предпочтения жанров/стран/режиссёров/актёров, групповые частоты и co-view.
Дополнительно проверены относительные предпочтения метаданных и ранги источников
кандидатов. Последние две группы оказались полезнее локальных агрегатов интересов.

В co-view графе используются до 100 последних пар пользователя, до 150 соседей
объекта, поддержка от трёх пользователей. Личные агрегаты считают полную доступную
историю. Кандидаты дедуплицируются, просмотренные объекты исключаются, будущие
положительные фильмы специально не добавляются.

Ranker: YetiRank, depth=6, lr=0.04, l2=8, до 850 деревьев. Выбор числа деревьев —
по end-to-end validation NDCG@10. Метрика сохраняет промахи отбора кандидатов.

## Запуск

Для другого компьютера рекомендуется [Docker-инструкция](../baseline_docker/README.md):
она принимает сырые train/test CSV, обучает модель один раз и повторно использует
сохранённые веса. Общая подготовка окружения и данных — в [корневом README](../README.md).

Исторический CPU strong можно воспроизвести из корня проекта:

```bash
baseline/.venv/bin/python -u -m baseline.pipeline run
baseline/.venv/bin/python -u -m baseline.strong reserve
baseline/.venv/bin/python -u -m baseline.strong prepare --variant expanded
baseline/.venv/bin/python -u -m baseline.strong train --variant expanded
```

Нужны `KION_DATASET/data_original.zip` и распакованные русские метаданные.
Конфигурации находятся в `configs/`, модели и расчётные таблицы — в `artifacts/`.
Для GPU-абляций используется `run_refined.py`; команды — в [REFINED_PLAN.md](REFINED_PLAN.md).

## Проверки и подробные отчёты

```bash
baseline/.venv/bin/python -m unittest discover -s baseline/tests -v
```

- [STRONG_RESULTS.md](STRONG_RESULTS.md): кандидаты, абляции и отложенные пользователи.
- [REFINED_RESULTS.md](REFINED_RESULTS.md): 21 GPU-модель, семь вариантов и три seed.
- [LEAKAGE_AUDIT.md](LEAKAGE_AUDIT.md): проверка временного отсечения признаков.
- [STRONG_PLAN.md](STRONG_PLAN.md): формулы и полный исторический протокол.
- [GPU_TRAINING.md](GPU_TRAINING.md): дополнительные агрегаты и логирование.

В KION сохранена дата последнего просмотра пары. `total_dur` и `watched_pct`
исключены из исторических признаков. Пропуск события — не подтверждённый отказ;
метаданные считаются статичными. Эти ограничения важны при интерпретации качества.
