# Усиление ручного baseline

## Границы подхода

Все дополнительные признаки заданы вручную: частоты, доли, временное затухание,
совпадения метаданных и нормированные счётчики совместных просмотров. Обучаемых
эмбеддингов, ALS, EASE и нейросетей в этом baseline нет. Обучается только CatBoost.

## Зафиксированный протокол

- Сохранить исходный baseline и его артефакты без изменений.
- Использовать исходные 30 000 пользователей и временные train/validation-срезы.
- До экспериментов выбрать ещё 30 000 пользователей, не пересекающихся с ними.
  Seed 20261023; список и SHA256 — `artifacts/strong/holdout_protocol.json`.
- Разрабатывать только по validation. Исходный test уже раскрыт; повторно
  использовать его метрики для настройки нельзя.
- Итоговая проверка новых пользователей относится к той же известной неделе,
  а не к новому временному периоду. Это ограничение нужно сохранить в отчёте.

## Эксперименты

1. **fixed:** 74 исходных + 81 дополнительный ручной признак на прежних кандидатах.
2. **expanded:** те же признаки, кандидаты дополнены соседями просмотренных объектов,
   популярностью за 3 дня и популярностью в возрастной группе.
3. **fixed/no_co:** абляция признаков совместных просмотров на прежних кандидатах.
4. После фиксации моделей — однократная проверка на отложенных пользователях.

Число деревьев выбирается по фактической end-to-end NDCG@10 на validation:
учитываются все положительные объекты, включая промахи генерации кандидатов.
Дополнительно измеряются Recall@10, MAP@10, покрытие кандидатов, парный bootstrap,
расход времени и памяти. Цель — подтвердить улучшение, а не достичь заранее
назначенного значения метрики.

## Вычисления и корректность

Полная история выбранных пользователей сохранена. Для co-view графа используется
не более 100 последних доступных пар каждого пользователя; это фиксированное
определение признака для ограничения влияния сверхактивных пользователей.
Граф строится заново на прошлом каждой точки, минимум поддержки 3,
150 соседей на объект. Самосвязи удаляются.

В офлайн-таблицах validation считаются только пользователи с будущими положительными
объектами — ровно те же пользователи, которых учитывала исходная метрика.
Это оптимизация вычислений, не признак и не алгоритм выбора пользователей в продукте.
Кандидаты строятся только по прошлому; положительные объекты не добавляются.
Пользователи с промахами генерации остаются в знаменателе метрик.

## Команды из корня репозитория

```bash
baseline/.venv/bin/python -u -m unittest discover -s baseline/tests -v
baseline/.venv/bin/python -u -m baseline.strong reserve
baseline/.venv/bin/python -u -m baseline.strong prepare --variant fixed
baseline/.venv/bin/python -u -m baseline.strong train --variant fixed
baseline/.venv/bin/python -u -m baseline.strong prepare --variant expanded
baseline/.venv/bin/python -u -m baseline.strong train --variant expanded
baseline/.venv/bin/python -u -m baseline.strong train --variant fixed --ablation no_co
baseline/.venv/bin/python -u -m baseline.strong final
```

Конфигурация — `configs/strong.json`. Команда `final` сохраняет контрольные суммы
моделей до доступа к итоговым меткам; повторная итоговая оценка в том же каталоге
запрещена. Все вычисления выполняются только через `baseline/.venv`.

## Формулы дополнительных признаков

Для объектов i и j: `co(i,j)` — число пользователей, у которых обе пары входят
в ограниченную прошлую историю; `n(i)` — число пользователей объекта.
Сходство: `co / sqrt(n(i)*n(j)) * co/(co+10)`, поддержка не меньше 3.
Сохраняются 150 лучших соседей каждого объекта. Признаки пары — сумма, максимум,
число поддерживающих соседей, среднее по истории, суммы по последним 1/3/5 парам
и суммы с экспоненциальным затуханием 7/30 дней. Это детерминированные агрегаты.

Сглаженная популярность в группе: `(count(group,item)+100*p(item))/(count(group)+100)`.
Группы: возраст, пол, наличие детей, доход и возраст×пол; окна 7 и 30 дней.
`p(item)` берётся из глобальной прошлой популярности за 30 дней. Дополнительно
используются число наблюдений и отношение сглаженной вероятности к глобальной.

Новые метаданные: актёры, студии, тип контента и возрастной рейтинг. Для каждой
группы задаются сумма и максимум предпочтений, доля по всей истории и за неделю,
взвешенная доля с затуханием 30 дней, совпадения с последней и тремя последними
парами. При одинаковых датах порядок определяется item_id; это порядок агрегатных
строк, а не достоверная последовательность сеансов.

Сравнение v1 с новой версией не является чистой абляцией всех дополнительных
признаков: также изменены learning_rate (0.05 → 0.04), l2_leaf_reg (3 → 8),
максимум итераций (700 → 850) и выбор числа деревьев по отчётной NDCG.
Для оценки вклада co-view применяется отдельная абляция при одинаковых
кандидатах, параметрах и процедуре выбора деревьев.

Оценка co-view для генерации кандидатов: сумма сходств с просмотренными объектами
с весом `0.25 + 0.75*exp(-days_since_watch/30)`. После удаления просмотренных
выбираются до 100 объектов. Эти веса фиксированы вручную.

## Завершение

Все три эксперимента выполнены. По validation выбран expanded: 825 деревьев,
NDCG@10 = 0.16041. После фиксации модели выполнена однократная контрольная оценка:
NDCG@10 = 0.15272 против 0.13537 у исходной модели на тех же новых пользователях.
Прирост 12.82%, положительный 95% bootstrap-интервал разницы.
Результаты, абляции и ограничения — в `STRONG_RESULTS.md`.
