# Обучение ручного baseline на GPU

## Что изменено

Новый вариант сохраняет кандидатов `expanded` и 155 признаков v2. Добавлены
58 ручных признаков (всего 213):

- 21 агрегат для жанров, стран и режиссёров: частоты, доли, затухание за 30 дней,
  совпадения с последними 1/3 доступными парами. Эти измерения дополняют прежние
  простые жанровые/страновые/режиссёрские частоты временными предпочтениями.
- 28 признаков распределения предпочтений по семи полям метаданных: энтропия,
  концентрация, масса токенов кандидата и её затухание с масштабом 7 дней.
  Каждая историческая пара делит единичную массу поровну между своими токенами;
  концентрация — сумма квадратов вероятностей, энтропия — `-sum(p*log(p))`.
- Четыре признака совместных просмотров: минимальная давность связанного объекта
  истории, сумма квадратов сходства, доля связанных объектов истории,
  максимальное сходство с затуханием за 7 дней. Нет связи: давность 999,
  остальные значения 0.
- Пять признаков жизненного цикла объекта: дни с первого/последнего наблюдения,
  доли событий последних 7/3 дней, среднее число событий на день наблюдения.
  Это возраст наблюдения в данных, а не дата публикации фильма.

Все определения фиксированы вручную, история строго раньше cutoff. Длительность
и процент просмотра не используются. Даты — последние доступные даты пар,
а не восстановленные сеансы. Полные личные истории сохранены.

Признаки включаются через `extended_aggregates`, старые эксперименты не меняются.
Качество новых признаков пока не измерено полным обучением; улучшение — гипотеза.

## Запуск

В обычном терминале компьютера:

```bash
cd /home/guyder/Проекты/tbank-rnd
baseline/.venv/bin/python -u -m baseline.run_training
```

По умолчанию используется GPU 0, YetiRank Classic, глубина 6, максимум 850 итераций,
до 75% памяти GPU для CatBoost. Признаки рассчитываются на CPU. Перед их расчётом
выполняется маленькое настоящее обучение на выбранном backend: недоступность GPU
сразу остановит запуск с ошибкой. Автоматического перехода на CPU нет.

Необходимы существующие артефакты `artifacts/default` и модель
`artifacts/strong/expanded/model.cbm`; дополнительных установок скрипт не делает.
Графы из `artifacts/strong` переиспользуются только при совпадении параметров
и cutoff. Если кэша нет, граф будет построен в новой папке запуска.

Скрипт выводит путь `baseline/artifacts/runs/<UTC-время>/`. Для работы после
закрытия терминала можно использовать `nohup`:

```bash
nohup baseline/.venv/bin/python -u -m baseline.run_training > baseline/artifacts/gpu_launcher.log 2>&1 &
```

Последние сообщения: `tail -f baseline/artifacts/gpu_launcher.log`.
Повторный запуск создаёт новую папку; продолжение прерванного обучения пока
не предусмотрено. Для выбора другой карты: `--devices 1`.

## Логи и результаты

В папке запуска сохраняются:

- `run.log`: версии библиотек, команды, подготовка данных, итерации и ошибки;
- `status.json`: этап, завершение/ошибка, время, Python и SHA256 исходников;
- `config.json`, `source/`: параметры и копии исходников;
- `expanded/manifest.json`: размеры и даты выборок, время подготовки;
- `expanded/learning_curve.json`, `catboost_parameters.json`: история обучения
  и фактические параметры CatBoost;
- `expanded/metrics.json`: end-to-end NDCG@10, Recall@10, MAP@10, покрытие
  кандидатов, сравнения с v1/v2 на тех же кандидатах и bootstrap-интервалы;
- `expanded/model.cbm`, `feature_importance.csv`, `validation_*_per_user.csv`.

Число деревьев выбирается на validation с учётом промахов retrieval. Встроенная
метрика CatBoost нормирована иначе; итоговую метрику смотри в `metrics.json`.
Известный holdout повторно не оценивается. GPU и CPU могут дать разные модели;
прирост нельзя заранее приписывать только признакам.

Когда обучение закончится, передай агенту путь папки запуска: логи уже будут
в репозитории, копировать их в чат не нужно. `status=completed` означает, что
пройдены обучение, сохранение модели и оценка.

## Короткая проверка на CPU

```bash
baseline/.venv/bin/python -u -m baseline.run_training --smoke
baseline/.venv/bin/python -m unittest discover -s baseline/tests
```

Smoke использует 300 пользователей разработки, полную их историю, глобальные
агрегаты по прошлому всех пользователей, все четыре временных среза и всего
три итерации. Он проверяет также оценку, сравнение с v2 и сохранение артефактов.
Его метрики не являются результатом полноценного эксперимента.
