# Рекомендации фильмов KION: ручной baseline и генерация Semantic IDs

Исследование альтернатив ручным признакам в рекомендательной системе. Сначала
построен сильный CatBoost на временных, контентных и поведенческих агрегатах.
Затем реализован генеративный рекомендатель: модель кодирует фильмы Semantic IDs
и предсказывает эти коды по истории пользователя.

**На текущем этапе ручной baseline сильнее.** Лучший генеративный вариант
превосходит популярность, но уступает CatBoost. Ниже описаны оба решения,
результаты и запуск на другом компьютере.

## 1. Baseline: кандидаты и CatBoost на ручных признаках

### Задача и данные

Используется русскоязычный [KION](KION_DATASET/README.md): 5 476 251 взаимодействие
из `data_original.zip`. Рекомендуем новые для пользователя фильмы на следующие
семь дней. Строка датасета — агрегированная пара user–item с датой **последнего**
просмотра, а не отдельный сеанс. Отсутствие просмотра не означает явный отказ.

Для разработки выбирались 30 000 пользователей с полной доступной историей.
Глобальные частоты и совместные просмотры считаются по прошлому всех пользователей.
Обучающие cutoff: 19/26 июля и 2 августа 2021; validation — 9–16 августа.
История всегда строго раньше cutoff, положительные метки — из следующей недели.
`total_dur` и `watched_pct` не используются: неизвестно, какими они были в прошлом.
Метаданные считаются статичным снимком.

### Как устроено решение

1. **Отбор кандидатов.** Объединяются популярные фильмы, фильмы предпочитаемых
   жанров, соседи просмотренных фильмов по совместным пользователям, свежая
   популярность и спрос в возрастной группе. Повторы и просмотренные фильмы удаляются.
2. **Ручные признаки.** Активность и давность, популярность в нескольких окнах,
   ускорение спроса, жанровые и другие контентные предпочтения, демографические
   группы, co-view и информация об источнике кандидата. Co-view — расчётная
   статистика совместных просмотров, отдельная нейросеть для неё не обучается.
3. **Ранжирование.** `CatBoostRanker`, YetiRank, глубина 6, learning rate 0.04,
   l2=8, максимум 850 деревьев. Число деревьев выбирается по validation NDCG@10,
   включая положительные объекты, не попавшие в кандидаты.

Исторический CPU-вариант `strong/expanded` использует 155 признаков. Позже на GPU
проверены дополнительные группы; для Docker выбран `combined`, 191 признак,
seed 44. Описание признаков и абляций — в [baseline](baseline/README.md).

### Полученные результаты

Метрики ниже — макросредние по 3328 тёплым пользователям одной validation-недели.

| Модель | NDCG@10 | Recall@10 | MAP@10 |
|---|---:|---:|---:|
| Популярность | 0.12330 | 0.18897 | 0.08363 |
| Исходный CatBoost v1 | 0.14197 | 0.21253 | 0.09810 |
| CatBoost strong/expanded, CPU, 155 признаков | **0.16041** | 0.23361 | **0.11351** |
| CatBoost combined, GPU, seed 44, 191 признак — Docker-рецепт | 0.16036 | **0.23466** | 0.11336 |

GPU `combined` в среднем по seed 42/43/44 получил NDCG@10 **0.15964 ± 0.00070**,
на 1.66% выше GPU v2. Исторический CPU-запуск остался чуть лучше по NDCG;
увеличение числа признаков само по себе не гарантирует улучшения.

Отдельно CPU strong проверен на 3456 отложенных тёплых пользователях недели
16–23 августа: NDCG@10 **0.15272**, Recall@10 **0.22930**, MAP@10 **0.10455**,
против NDCG@10 0.13537 у v1. Это другая популяция в уже известной неделе,
а не независимый новый временной тест. Подробности:
[strong](baseline/STRONG_RESULTS.md), [GPU-абляции](baseline/REFINED_RESULTS.md).

### Воспроизведение на другом компьютере

Понадобятся Docker, Python 3.12 и [uv](https://docs.astral.sh/uv/).
Для GPU нужны совместимый NVIDIA-драйвер и NVIDIA Container Toolkit;
CPU-режим поддерживается, но может работать дольше и дать другие числа.
Все команды выполняются из корня клонированного репозитория.
Проверенный сценарий — Linux x86_64 и Bash.

Подготовьте окружение для утилит подготовки данных и локальных запусков:

```bash
uv venv --python 3.12 baseline/.venv
uv pip install --python baseline/.venv/bin/python \
  -r baseline/requirements.lock.txt \
  -r generative_docker/requirements.lock.txt \
  --extra-index-url https://download.pytorch.org/whl/cu126
```

Поместите полный русскоязычный архив в `KION_DATASET/data_original.zip`.
Внутри должны быть `data_original/interactions.csv`, `users.csv` и `items.csv`.
Отдельный `interactions.csv.zip` в исходной рабочей копии оказался неполным,
поэтому для воспроизведения используется полный `data_original.zip`.

Создайте новую директорию с внешним train/test; выбранный путь не должен существовать:

```bash
DATA_DIR="$HOME/kion-recsys-data"
baseline/.venv/bin/python -m baseline_docker.prepare_kion \
  --archive KION_DATASET/data_original.zip \
  --output "$DATA_DIR" --test-cutoff 2021-08-16

./baseline_docker/build.sh
BASELINE_GPU=gpu ./baseline_docker/run.sh "$DATA_DIR"
```

Без GPU замените `BASELINE_GPU=gpu` на `BASELINE_GPU=cpu`. Без этой переменной
обёртка автоматически определяет доступность GPU.

Первый запуск обучает модель, сохраняет `model.cbm/model.json`, затем оценивает
внешний test. Повторный запуск загружает модель без обучения. Последний отчёт —
`metrics.json`, подробные логи и предсказания — `runs/<UTC>/` внутри `DATA_DIR`.

Docker воспроизводит **рецепт**, а не обещает validation-числа из таблицы:
внешний test — другой интервал, а выборка train-users может отличаться.
Внешняя оценка включает cold users; для сравнения с исторической warm-only
validation смотрите соответствующие отдельные блоки отчёта.

Если сохранились локальные веса исходного проекта, их можно перенести командой
`baseline/.venv/bin/python -m baseline_docker.export_best --data-dir "$DATA_DIR"`;
они не входят в Git или Docker-образ.
Полный CSV-контракт, настройки и экспорт — в [baseline_docker](baseline_docker/README.md).

## 2. Generative: рекомендации через Semantic IDs

### Текущая реализация

Это адаптация идеи TIGER под KION. Модель генерирует код отдельного рекомендуемого
фильма; десять рекомендаций получаются поиском нескольких вероятных кодов.
Готового ручного списка кандидатов перед генератором нет.

```text
Метаданные фильма → TF-IDF/SVD → RQ-VAE → Semantic ID
                                              ↓
История фильмов и давность → Transformer → beam search по SID → рекомендации
```

Лучший измеренный рецепт использует **локальные TF-IDF/SVD-векторы размерности 96**.
RQ-VAE сжимает их в 32-мерное пространство и кодирует тремя словарями по 64 центра.
Четвёртый код различает фильмы с одинаковой тройкой. Tokenizer обучается 500 эпох,
Adagrad, lr=0.05; затем замораживается.

Генератор — encoder-decoder Transformer: d_model=128, четыре головы, по два слоя
encoder/decoder. В истории четыре кодовых embedding фильма суммируются в один
вектор, к нему добавляется кодирование давности. На выходе decoder предсказывает
SID по одному токену; trie ограничивает поиск существующими фильмами, просмотренные
исключаются. Обучение — до 30 эпох, early stopping по validation NDCG@10.

Каталог фиксируется до первого обучающего cutoff: 14 947 фильмов. Истории
сохраняются полностью, encoder использует последние 128 объектов с сохранением
всей пограничной даты. Новые положительные фильмы вне каталога остаются в метрике,
хотя генератор не может их рекомендовать. Потолок доступности positives на
validation — около 87.8% по среднему пользовательскому recall.

В исследовательском default сейчас E5-base; он **не является лучшим измеренным
решением**. Для воспроизводимого запуска выбран отдельный TF-IDF-рецепт.

### Результат

| Модель | NDCG@10 | Recall@10 | MAP@10 |
|---|---:|---:|---:|
| Популярность | 0.12330 | 0.18897 | 0.08363 |
| **TF-IDF/SVD → RQ-VAE → Transformer** | **0.14054** | **0.20995** | **0.09785** |
| CatBoost strong/expanded, исторический reference | 0.16041 | 0.23361 | 0.11351 |

Генеративная модель выше популярности примерно на 14% по NDCG, но ниже CatBoost
примерно на 12.4%. Это сравнение целых систем: их способы получения рекомендаций
различаются. Оно не изолирует вклад только ранжировщика или только признаков.

### Воспроизведение на другом компьютере

Используйте окружение и директорию `DATA_DIR`, подготовленные выше. `items.csv`
должен содержать название `title`; утилита `prepare_kion` сохраняет его автоматически.

```bash
./generative_docker/build.sh
SID_GPU=gpu ./generative_docker/run.sh "$DATA_DIR" --inference-device cuda
```

Для CPU: `SID_GPU=cpu ./generative_docker/run.sh "$DATA_DIR"`.
При первом запуске обучаются TF-IDF/SVD, RQ-VAE и генератор. Сохраняются
`sid_model.pt` с генератором и таблицей SID, `sid_model.json` и `sid_metrics.json`.
Повторная команда использует готовую модель. Без явного `--inference-device cuda`
внешняя генерация выполняется на CPU. Никакие pretrained-модели скачивать не нужно.

Файлы модели и последнего отчёта не конфликтуют с файлами CatBoost, поэтому
оба контейнера могут использовать один набор CSV. Логи находятся в `runs/sid_<UTC>/`.
Конфигурация, хеши входов и происхождение модели сохраняются вместе с результатами.

Для исторического эксперимента без Docker, с исходной выборкой пользователей,
потребуются также распакованные русские метаданные:

```bash
unzip KION_DATASET/data_original.zip -d KION_DATASET
baseline/.venv/bin/python -u -m research.generative_recsys.run --device cuda \
  --config research/generative_recsys/configs/best_tfidf_rqvae.json
```

Этот исследовательский запуск читает сохранённый список dev-users из
`baseline/artifacts/default/sample_users.csv`; если его нет, сначала выполните
`baseline/.venv/bin/python -m baseline.pipeline run`. Для нового компьютера без
локальных артефактов проще использовать Docker-путь: он сам выбирает train-users.

Контракт данных, настройка параметров и перенос точных лучших весов:
[generative_docker](generative_docker/README.md). Все измеренные результаты:
[research/generative_recsys/RESULTS.md](research/generative_recsys/RESULTS.md).

## 3. Эксперименты, ограничения и future work

### Что уже проверено

Генераторы ниже оценены на тех же 3328 пользователях validation, seed 42.

| Представление фильмов и tokenizer | NDCG@10 | Recall@10 | MAP@10 |
|---|---:|---:|---:|
| TF-IDF/SVD + residual k-means | 0.13568 | 0.19986 | 0.09512 |
| **TF-IDF/SVD + RQ-VAE** | **0.14054** | **0.20995** | **0.09785** |
| Sentence-T5 + RQ-VAE | 0.13651 | 0.20084 | 0.09617 |
| multilingual E5-base + RQ-VAE | 0.13593 | 0.20333 | 0.09528 |
| E5-base + alternating + affine RQ-VAE | 0.13512 | 0.20125 | 0.09439 |
| CatBoost combined, GPU seed 44 | 0.16036 | 0.23466 | 0.11336 |
| CatBoost strong/expanded, CPU | 0.16041 | 0.23361 | 0.11351 |

Переход на языковые embeddings не дал улучшения. Sentence-T5 checkpoint
ориентирован на английский язык; E5 поддерживает русский, но замена сама по себе
не решила проблему. Высокая cosine similarity и число кластеров HDBSCAN не
оказались достаточными критериями выбора encoder.

В RQ-VAE обнаружилось долгое раннее плато: decoder почти возвращал средний
вектор каталога, первый словарь использовал один код. За 1000 эпох с lr=0.1
модель частично выходила из этого состояния. Проверены совместное обучение,
поочерёдные обновления словарей и сети, а также affine reparameterization — общий
обучаемый сдвиг и масштаб центров каждого словаря.

| RQ-VAE на E5, 1000 эпох | Reconstruction ↓ | Выигрыш к среднему вектору | Занятые коды |
|---|---:|---:|---|
| Joint, lr=0.1 | 0.122429 | 11.09% | 3 / 52 / 56 |
| Alternating, lr=0.1 | **0.119462** | **13.25%** | 7 / 59 / 61 |
| Alternating, lr=0.4 | 0.137746 | −0.03% | 1 / 1 / 1 |
| Alternating + affine, lr=0.1 | 0.119599 | 13.15% | **38 / 62 / 53** |

Affine увеличил число различных троек SID с 5428 до 8952, но улучшения
рекомендаций не дал. Reconstruction — качество восстановления обучающих
векторов, а не рекомендаций. Использование всех центров не является обязательным
свойством RQ-VAE; важнее сохранение полезной информации.

Конфигурации, кривые, индивидуальные метрики и снимки кода полных запусков
сохранены в [results/](research/generative_recsys/results/). Подробности ручных
абляций — в [REFINED_RESULTS.md](baseline/REFINED_RESULTS.md), обзор литературы —
в [research/](research/README.md).

### Что стоит попробовать дальше

1. **Проверить RQ-VAE через непрерывный AE.** Сначала научить encoder/decoder
   восстанавливать фильмы без квантования; затем residual k-means и включение RQ.
   Это поможет отделить проблемы оптимизации сети от дискретного bottleneck.
2. **Проверить стабилизацию словарей.** AE warm-up, раздельные learning rates,
   несколько шагов словаря на шаг сети, EMA и восстановление неиспользуемых
   центров — отдельными абляциями с учётом вычислительного бюджета.
3. **Приблизить генератор к TIGER.** Передавать SID истории отдельными токенами
   вместо их суммы, проверить user-ID token и представление хронологии.
   Порядок внутри одного дня неизвестен, поэтому его нельзя считать достоверным.
4. **Добавить поведенческую информацию в представления фильмов.** Контентная
   близость не обязана совпадать с предпочтениями аудитории. Проверить совместное
   обучение контента и взаимодействий с временным отсечением.
5. **Усилить контроль сравнения.** Несколько seed и временных validation-окон,
   отдельный эксперимент на одинаковых кандидатах, затем новый закрытый test.
   Текущие bootstrap-интервалы не учитывают весь процесс выбора моделей.
6. **Продолжить baseline-абляции.** Проверить sources+lift без interest и больший
   бюджет деревьев: многие GPU-модели выбрали предельные 850 итераций.

Основное ограничение данных остаётся общим: дата последнего просмотра не
восстанавливает полноценную последовательность сеансов, а статичные метаданные
не дают исторических снимков каталога. Проект показывает результаты на этом
доступном протоколе, а не качество готовой производственной системы.
