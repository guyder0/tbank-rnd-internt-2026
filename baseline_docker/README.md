# CatBoost-рекомендатель в Docker

Контейнер обучает ручной baseline на `train.csv`, сохраняет модель и оценивает
её на внешнем `test.csv`. При повторном запуске обучение пропускается.

Используется GPU-рецепт **combined, seed 44**: 191 ручной признак,
CatBoostRanker/YetiRank, depth=6, lr=0.04, l2=8, до 850 деревьев.
Историческая validation: **NDCG@10 0.16036, Recall@10 0.23466, MAP@10 0.11336**.
Это не гарантированный результат на новых входных CSV. История развития и
сравнение с CPU strong — в [baseline](../baseline/README.md).

## Быстрый запуск

Установка окружения и описание проекта — в [корневом README](../README.md).
Команды выполняются из корня репозитория.

```bash
./baseline_docker/build.sh

# output должен быть новой, ещё не существующей директорией.
DATA_DIR="$HOME/kion-recsys-data"
baseline/.venv/bin/python -m baseline_docker.prepare_kion \
  --archive KION_DATASET/data_original.zip \
  --output "$DATA_DIR" --test-cutoff 2021-08-16

BASELINE_GPU=gpu ./baseline_docker/run.sh "$DATA_DIR"
```

Для CPU используйте `BASELINE_GPU=cpu`. Без переменной `BASELINE_GPU` GPU
определяется автоматически. Другое имя образа задаётся через `BASELINE_IMAGE`.
Повтор той же команды использует сохранённую модель.

## Входные данные

Контейнер получает директорию как `/data`:

```text
train.csv       # история до начала test
test.csv        # будущие положительные взаимодействия
users.csv       # пользовательские метаданные
items.csv       # метаданные фильмов
dataset.json    # явные даты test; рекомендуется
```

У `train.csv` и `test.csv` нужны `user_id,item_id,last_watch_dt`; вместо
`last_watch_dt` допускается `date`. ID — неотрицательные целые, даты — календарные
без времени. Внутри файла должна быть одна строка на пару user–item. Лишние поля
взаимодействий игнорируются; таблицы кандидатов или готовые отрицательные метки
передавать не нужно.

`users.csv`: `user_id,age,income,sex,kids_flg`.

`items.csv`: `item_id,content_type,release_year,age_rating,for_kids,genres,countries,directors,actors,studios`.

Пропуски демографии допустимы. Дубли ID метаданных, неизвестные фильмы, пустые
взаимодействия и нарушения хронологии отклоняются. В `dataset.json`:

```json
{"test_cutoff": "2021-08-16", "test_end_exclusive": "2021-08-23"}
```

Train должен целиком лежать раньше cutoff, test — в указанной семидневной неделе.
Если файла нет, cutoff выводится из минимальной даты test. Лучше задавать его
явно, чтобы отсутствие событий в первый день не сдвигало задачу.

## Обучение и повторное использование модели

Последняя неделя train служит внутренней validation, перед ней строятся три
обучающих недельных среза. Признаки каждого среза используют только его прошлое.
До 30000 train-users выбираются с seed 42; их истории сохраняются полностью.
Общие статистики считаются по всем пользователям train.

Число деревьев выбирается по end-to-end validation NDCG@10. Дополнительного refit
после выбора нет. Будущий внешний test не используется для выбора модели.

После обучения появляются:

- `model.cbm`, `model.json` — веса, конфигурация, хеши и происхождение;
- `metrics.json` — последний успешный отчёт на внешнем test;
- `runs/<UTC>/` — журнал, config, входные хеши, per-user метрики, рекомендации,
  а при обучении также кривые и важности признаков.

Модель сохраняется до оценки test. Повторный запуск загружает её и не
инициализирует GPU для обучения. Предсказания CatBoost всегда выполняются на CPU.
Повреждённая модель или несовместимые настройки приводят к ошибке, а не скрытому
переобучению. Одновременная запись защищена lock; последняя успешная метрика
не заменяется неудачным запуском.

Параметры можно изменить JSON-файлом внутри mounted-директории:

```bash
./baseline_docker/run.sh "$DATA_DIR" --config /data/config.json
```

Допускается подмножество полей `default_config.json`; схема признаков фиксирована.
При загрузке модели её config используется автоматически. Для другого обучения
выберите отдельную директорию модели.

## Перенос исходных лучших GPU-весов

Если локальные артефакты проекта сохранились, до первого запуска:

```bash
baseline/.venv/bin/python -m baseline_docker.export_best --data-dir "$DATA_DIR"
./baseline_docker/run.sh "$DATA_DIR"
```

Экспортируется combined seed44 из `baseline/artifacts/refined/full_v1/`.
Веса не входят в Git или Docker-образ и не обучались на смонтированном train.
Происхождение фиксируется в metadata. Они использовали validation до 16 августа
2021, поэтому более ранний test для них запрещён.

## Как читать отчёт

Метрики: NDCG/Recall/MAP при K=1/5/10/20, Precision@10, HitRate@10, candidate
recall, покрытие каталога, сравнение с популярностью и bootstrap-интервалы.
Основная оценка включает всех test-users с новыми положительными объектами;
отдельно приведены warm/cold и группы длины истории. Промахи отбора кандидатов
остаются в знаменателях. Ранее просмотренные пары исключаются из test-целей.

Исторические числа проекта относятся к warm-only validation. Для сопоставления
смотрите блок `warm`, но учитывайте другой временной интервал и состав пользователей.
Внешние исходы внутри test-недели не добавляются к истории.

## Проверка и GPU

```bash
baseline/.venv/bin/python -m unittest discover -s baseline_docker/tests -v
```

`BASELINE_GPU=gpu` требует GPU при обучении. Автоматический режим при
недоступности GPU выбирает CPU с причиной в журнале; ошибки основного обучения
не маскируются повтором на CPU. Если Docker сам не запускает контейнер с GPU,
проверьте NVIDIA Container Toolkit или выполните CPU-запуск.

Build context содержит только необходимые исходники; данные, окружение и модели
в образ не копируются. Версии Python-пакетов закреплены в `requirements.txt`.
